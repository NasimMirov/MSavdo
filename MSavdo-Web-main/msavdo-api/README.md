# M.Savdo — Интернет-сервис выкупа товаров из Китая

Сервис выкупа товаров с китайских оптовых и розничных платформ (1688.com, Pinduoduo, Taobao) с пересчетом цен в таджикские сомони (TJS), авто-категоризацией, строгим регламентом возврата средств и заказом в WhatsApp.

---

## 🧩 Установка и настройка Chrome-расширения (Manifest V3)

Файлы расширения находятся в папке `/chrome-extension/`:
- `manifest.json` — конфигурация Manifest V3 с фоновым Service Worker.
- `background.js` — Service Worker, исключающий ошибки CORS, Mixed Content и CSP блокировки сайтов 1688/Pinduoduo.
- `content.js` — скрипт, добавляющий кнопку «📥 Импорт в M.Savdo» на карточки товаров.
- `popup.html` и `popup.js` — окно проверки связи с сервером и настройки URL.

### Пошаговая инструкция:
1. Откройте в браузере Google Chrome страницу: `chrome://extensions/`
2. В правом верхнем углу включите тумблер **«Режим разработчика»** (Developer mode).
3. Нажмите кнопку **«Загрузить распакованное расширение»** (Load unpacked).
4. Выберите папку `chrome-extension` из этого проекта. (Если расширение уже было установлено, нажмите кнопку с иконкой стрелки **«Обновить»** 🔄 на карточке расширения).
5. Нажмите на значок пазла в панели браузера и закрепите иконку **M.Savdo**.
6. Кликните по иконке M.Savdo в браузере и нажмите **«⚡ Проверить подключение»**.
   - Должна загореться зеленая плашка: «✓ Связь установлена!».
   - Если сервер запущен на Flask (`python3 app.py`), оставьте адрес `http://127.0.0.1:5000`.
   - Если вы тестируете проект прямо в онлайн-превью, укажите адрес вашего превью или `http://127.0.0.1:3000`.
7. Перейдите на любую страницу товара на **1688.com**, **pinduoduo.com (yangkeduo.com)** или **taobao.com**.
8. В правом нижнем углу появится плавающая кнопка **«📥 Импорт в M.Savdo»**.
9. Нажмите её — откроется удобное окно с подтверждением названия, цены в юанях, расчетом цены в сомони (TJS) и кнопкой быстрой отправки!

## 🚀 Запуск Python сервера (Flask + SQLite)

```bash
# 1. Установите Flask (если не установлен)
pip install flask

# 2. Запустите приложение
python3 app.py
```
После запуска сервер доступен по адресу: **http://127.0.0.1:5000**
- Главная витрина: `http://127.0.0.1:5000/`
- Корзина: `http://127.0.0.1:5000/cart`
- Правила сервиса: `http://127.0.0.1:5000/rules`
- Админ-панель: `http://127.0.0.1:5000/admin`
- API импорта: `POST http://127.0.0.1:5000/api/add-product`
- Проверка связи: `GET http://127.0.0.1:5000/api/ping`

## Защита админ-панели (Node.js сервер)

Витрина на Vercel использует `vercel.json` в корне проекта для передачи запросов `/product/*`, `/robots.txt`, `/sitemap.xml` и `/sitemap-products-*.xml` на API Amvera. Это необходимо для прямых ссылок на товары и индексации; остальные запросы обслуживаются витриной как прежде.

Вход в админ-панель выполняется через Telegram Login. В BotFather выберите `@msavdo_login_bot`, откройте `Login Widget`, зарегистрируйте `https://msavdo.shop` как Allowed URL и получите Client ID. В серверных переменных окружения задайте `TELEGRAM_LOGIN_CLIENT_ID`, `ADMIN_TELEGRAM_ALLOWED_IDS` с ровно двумя числовыми Telegram user ID и `ADMIN_JWT_SECRET` случайным значением не короче 32 байт. Секрет можно сгенерировать командой `node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"`. Не коммитьте секрет.

Сервер проверяет подпись Telegram ID token, issuer, audience, срок действия, одноразовый nonce и наличие Telegram ID в allowlist. Парольный вход отключён. Админская сессия живёт два часа и хранится только в cookie `HttpOnly`, `Secure`, `SameSite=Strict`; панель и API должны использовать HTTPS-домены одного сайта. Добавьте точный frontend origin в `ADMIN_ALLOWED_ORIGINS`. За reverse proxy задайте доверенное число прокси в `TRUST_PROXY_HOPS`.

При запуске production-сервера выполняется однократное восстановление снимка каталога от 4 ноября 2026 года, если рабочая база содержит четыре известных стартовых товара, а снимок совпадает с ожидаемым хешем. Перед переносом создаётся копия рабочей БД. Совпадающие товары из снимка активируются; если ID или SKU уже принадлежат другой записи, текущая запись сохраняется, а товар из снимка импортируется отдельным черновиком с новыми ID и, при необходимости, уникальными SKU. Остальные отсутствующие товары/варианты добавляются, четыре стартовых товара переводятся в черновики. Заказы и остальные таблицы не заменяются; новые ID не используют значения, на которые ссылаются строки заказов. Копия сохраняется рядом с `/data/msavdo.db` с суффиксом `.before-catalog-restore-2026-11-04-<timestamp>.bak`; результат отмечается в `settings`, поэтому повторный запуск перенос не повторит.

### Резервные копии

Удаление товара скрывает его из каталога, но сохраняет запись и варианты. В разделе товаров админки отображаются последние 10 удалений; восстановление возвращает товар с вариантами и ценами в черновики для проверки перед публикацией. Старые удалённые записи автоматически не уничтожаются. Это не заменяет резервные копии и не восстанавливает товары, удалённые до внедрения этой функции.

База `/data/msavdo.db` и файлы `/data/uploads` находятся на постоянном диске Amvera, отдельно от собираемого приложения. Обычный деплой не должен их заменять; удаление диска или смена сервера не сохраняет эти данные автоматически.
В production демонстрационные товары автоматически не создаются, даже если каталог пуст; локальная среда разработки по-прежнему может их создавать.

Новые изображения, загруженные в редакторе из файла или буфера обмена, сохраняются в JPEG с небольшим полупрозрачным водяным знаком. Для них повторный знак при публикации не накладывается. Ранее загруженные файлы не изменяются; публичные фото товаров по-прежнему обрабатываются при выдаче.

В админке в разделе «Настройки» нажмите «Скачать резервную копию». ZIP содержит согласованный снимок SQLite и загруженные файлы. Скачивайте копии регулярно и после важных изменений, храните их вне сервера в защищённом месте: архив содержит заказы, сведения клиентов и настройки. Это ручное резервирование, не автоматическая внешняя копия. Фото, хранящиеся по внешним ссылкам, в ZIP не входят и могут исчезнуть у источника.

Для восстановления специалист должен остановить приложение, отдельно сохранить текущие `/data/msavdo.db` и `/data/uploads`, затем восстановить `msavdo.db` и содержимое `uploads` из выбранного архива в `/data` и запустить приложение. Перед заменой базы необходимо учесть файлы SQLite `-wal` и `-shm`; не подменяйте работающую базу. Восстановление перезаписывает данные, появившиеся после даты архива.

## Сборка и адрес API

`npm run build` очищает каталог `dist` и собирает туда клиентское приложение. Базовый URL API задаётся через `VITE_API_BASE_URL`: локально используется `https://213.21.0.251/`, а в production укажите origin облачного API. Если переменная в production не задана, клиент обращается к API на том же origin, что и сайт. Пример переменных находится в `.env.example`; переменные `VITE_*` встраиваются в клиентскую сборку и не должны содержать секреты.
